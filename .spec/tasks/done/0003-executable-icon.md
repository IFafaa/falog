# 0003: App icon

**Status:** done
**Area:** desktop, scripts

## Goal

Falog has an icon of its own, drawn once as SVG, and `falog.exe`, the window, the taskbar, the Start
menu shortcut and (later) the macOS and Linux launchers all show it.

## Context

The window icon was drawn in code (`icons::app_icon`): a rounded One Dark tile with an accent check
mark, which says "to-do app" but nothing about Falog, and the executable had no icon resource at all.

## Scope

- In: a new design (SVG master plus pixel-hinted 16 and 24 px copies), a committed rasterizer that
  regenerates PNGs, a multi-size `.ico` and a `.icns`; the window and taskbar icon; the `.ico`
  embedded in `falog.exe` on Windows; the Start menu shortcut; files a macOS `.app` bundle and a Linux
  desktop entry can pick up.
- Out: an MSI/MSIX installer, the `.app` bundle and desktop entry themselves (macOS/Linux port, 0012).

## Acceptance criteria

- [x] Explorer and the Start menu shortcut show the icon
- [x] The window icon and the `.ico` come from the same artwork
- [x] Builds on non-Windows targets are unaffected
- [x] Recognizable at 16 px on light and dark taskbars; not a plain check mark
- [x] `docs/icon-preview.png` shows it at every size; `design-system.md` has an "App icon" section
- [x] `fmt`, `clippy`, `test` green

## Plan

1. Three concepts as SVG in `docs/icon-concepts`, compared at 16–64 px on dark and light backgrounds;
   refine the strongest into `crates/falog-desktop/assets/icon/falog.svg` plus hinted
   `falog-16.svg` and `falog-24.svg`.
2. `tools/icon`: a standalone crate (outside the workspace, so release builds do not compile it) that
   rasterizes the masters with resvg and writes `png/falog-N.png`, `falog.ico` (BMP entries up to
   128 px, PNG at 256) and `falog.icns` (Apple's 824/1024 grid with a drop shadow), plus the preview.
3. `main.rs` loads the 256 px PNG through `eframe::icon_data::from_png_bytes`; `app_icon()` goes away.
4. `build.rs` embeds `falog.ico` with `winresource` when the target is Windows.
5. `install.ps1` sets the shortcut's `IconLocation` to the executable.

Risks: the `.icns` cannot be checked on Windows (written to Apple's documented format; `iconutil`
on a Mac can rebuild it from the PNGs if Finder disagrees). Explorer caches icons; a stale one after
reinstalling is the cache, not the build.

## Outcome

**Concept.** Three concepts were drawn in `docs/icon-concepts` and compared at 16–64 px on dark and
light taskbars (`concepts.png`):

1. *Speech bubble* holding log lines: reads well at 16 px, but it is every chat app's icon.
2. *Microphone* whose capsule holds the lines: the strongest silhouette, but it says "voice recorder",
   and Falog is a task board first.
3. *Spoken F*: an F whose middle arm is a voice fading out (two bars and a dot), next to a top arm
   that is a line already in the log. **Picked**: it is a monogram, so it is Falog's and nobody
   else's; it tells the product in one shape (what you say becomes a line in the log); it keeps an F
   silhouette down to 16 px; and it is drawn with the same rounded strokes as the Lucide icons in the
   UI. Two more drafts (a waveform settling into a list row, a bubble with a waveform) were dropped as
   too busy at 16 px.

Refinement: accent ink with a light-to-dark gradient on the One Dark tile, a 3-unit `#464b57` edge so
the tile holds on dark taskbars, and copies redrawn on the 16 and 24 px grids (24 px is the taskbar at
100 % scaling), because downscaling the master left half-pixel blur there.

**Files** (`crates/falog-desktop/assets/icon`, generated by `tools/icon` from the SVGs):

| Path | Used by |
|---|---|
| `falog.svg`, `falog-16.svg`, `falog-24.svg` | sources; `falog.svg` also for Linux `hicolor/scalable/apps` |
| `png/falog-{16,24,32,48,64,128,256,512,1024}.png` | window icon (256), Linux `hicolor/NxN/apps/falog.png` |
| `falog.ico` | `build.rs` (resource in `falog.exe`), `install.ps1` (Start menu shortcut) |
| `falog.icns` | macOS `Falog.app/Contents/Resources` with `CFBundleIconFile` = `falog` |

**Wiring.** `icons::app_icon()` loads `falog-256.png` (the hand-drawn check mark is gone; a test checks
the PNG decodes). `build.rs` embeds `falog.ico` through `winresource` on Windows targets only, and
sets the file description to "Falog" so Task Manager shows the name instead of the crate description.
`install.ps1` copies `falog.ico` next to the executable and points the shortcut at it.

**Checked:** the built `falog.exe` shows the icon in its resources (extracted with
`System.Drawing.Icon`), `docs/icon-preview.png` shows every size on both backgrounds. Not checked: the
`.icns` in Finder (written on Windows); the taskbar on a fresh install (the main session installs).

**Follow-ups:** the macOS `.app` bundle and Linux desktop entry pick these files up (task 0012). If
Finder rejects `falog.icns`, rebuild it from `png/` with `iconutil`.
